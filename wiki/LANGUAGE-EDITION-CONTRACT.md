# Human Infra 语言版本契约

## 目标结构

```text
多语言门户
  -> 独立语言版本
  -> 该语言的项目首页
  -> 专题 Portal
  -> 研究域、技术节点和证据来源
```

多语言门户只负责语言发现、版本状态、搜索路由和进入语言版本。它不承载研究结论，也不代替任何语言版本的首页。

## 语言版本准入

一个语言版本只有同时满足以下条件才可以标记为 `available`：

1. 拥有明确的内容语言代码和独立内容边界。
2. 拥有对应语言的项目首页、内容方针、版权说明和维护责任。
3. 核心专题、导航和引用边界已经本地化。
4. 搜索、编辑、历史版本和内部链接可以独立工作。
5. 有持续维护者，不以机器直译页面数量冒充语言版本成熟度。

筹备中的语言必须标记为 `planned`，不能生成空 Wiki、伪造词条数量或接受搜索路由。

## 路由与数据

- `portal/languages.json` 是语言状态与展示顺序的真相源。
- `available` 语言必须提供可访问的 MediaWiki 版本。
- 本地门户根据当前主机和 `WIKI_PUBLIC_PORT` 生成中文 Wiki 地址。
- 生产部署使用独立域名或反向代理时，必须显式更新路由配置，不得依赖本地端口推断。
- 词条数量优先从 MediaWiki API 获取；API 不可用时只显示版本状态，不展示过期硬编码数量。

## 模型边界

- 切换界面语言只改变用户界面，不构成新的内容语言版本。
- 单站翻译页面适合文档本地化，不等同于独立语言 Wiki。
- 各语言版本可以共享程序、皮肤、扩展和媒体基础设施，但正文、首页、模板、分类和审查状态分别治理。
- 跨语言对应关系必须通过稳定实体 ID 或明确的 interwiki 映射维护。
