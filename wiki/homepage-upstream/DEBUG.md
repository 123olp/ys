# 中文首页模板复用调试记录

## 现象

本地首页视觉上接近中文维基百科，但主体 DOM、页首和样式文件由项目人工重写。仓库只记录上游修订号，没有保存可复核的上游页面本体，因此无法证明页面确实来自官方模板，也无法阻止后续手工漂移。

## 假设与实验

| 假设 | 实验 | 结果 |
| --- | --- | --- |
| 记录修订号即可保证复用 | 从仓库重建官方首页原文 | 失败，仓库没有原文 |
| DOM 选择器相同即可视为同一模板 | 比较本地首页与官方 Wikitext | 失败，本地结构是手写压缩版本 |
| 固定快照加确定性生成器可以建立真相源 | 抓取官方 Wikitext、页首、CSS、渲染 HTML，校验哈希并重新生成 | 通过 |

## 根因

首页缺少不可变的上游快照和确定性生成链。人工维护的“相似 DOM”被错误地当成“复用官方模板”，导致设计来源、更新边界和漂移验证均不可执行。

## 修复

1. 固定保存官方首页、页首、TemplateStyles、渲染 HTML 和修订元数据。
2. 由生成器保留上游 `mp-2012` 外层结构，只替换已登记内容槽位。
3. 因 TemplateStyles 安全策略规范化官方横幅资源 URL，并由页首内容槽位替代上游 Wikipedia 标志背景；所有转换均显式登记。
4. 将快照哈希和生成产物一致性接入 `make validate`。

## 回归条件

- 快照文件必须与 `metadata.json` 中的 SHA-256 一致。
- 生成器的每个替换锚点必须且只能命中一次。
- 所有上游静态 `mp-2012*` ID 必须保留。
- 生成产物与重新构建结果必须逐字节一致。
