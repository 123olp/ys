# GATE-0002 历史年表必须通过机器契约校验

## 阻止条件

- 修改 `docs/reference/history-timeline/`、`docs/templates/history-event.md` 或任何年表 JSON 数据后，未通过 `make history-timeline-gate`。
- 年表 JSON 无法被 `timeline.schema.json` 校验。
- 必填文件缺失：`README.md`、`CONTRACT.md`、`GOVERNANCE.md`、`TOOLS.md`、三份 Schema、`timeline.json`、`sources.json`、`periods.json`、`example-events.json`。
- 事件 ID、来源卡 ID、时期 ID 重复或不符合 `HIT-*` / `SRC-*` / `period-*` 命名契约。
- 事件 `sources` 引用了未注册来源卡，或 `period_id` 引用了未注册时期。
- 日期、路径族、事件类型、证据等级、状态字段超出契约枚举。
- 治理契约 `governance/control-plane/history-timeline-contract.v1.yaml` 与实际文件路径不一致。

## 原因

- 严肃历史年表必须可机器复核、可版本化、可自动化门禁，不能只依赖人工阅读。
- 日期、来源、证据等级和生命周期状态是公共永生史的引用地基，任何漂移都会造成“来源看起来支持、实际不支持”的误读。

## 检查方式

- automated: 运行 `make history-timeline-gate`。
- automated: 运行 `python3 tools/validate_history_timeline.py`。
- manual: 检查治理契约 `governance/control-plane/history-timeline-contract.v1.yaml` 是否与 Schema 和 CI 步骤一致。

## 可操作错误提示

- `status=FAIL reason=history_timeline_schema` 表示事件数据不满足 Schema。
- `status=FAIL reason=history_timeline_missing_required_file` 表示工程包文件缺失。
- `status=FAIL reason=history_timeline_duplicate_event_id` 表示事件 ID 冲突。
- `status=FAIL reason=history_timeline_contract_mismatch` 表示机器契约与实际路径不一致。

## 最小修复

- [ ] 运行 `make history-timeline-gate`，读取具体 `reason`。
- [ ] 修正 JSON 字段、枚举值、日期格式或重复 ID。
- [ ] 若契约有意变化，先更新 `governance/control-plane/history-timeline-contract.v1.yaml` 和 Schema，再重新校验。
- [ ] 重新运行 `make history-timeline-gate` 直到 PASS。
