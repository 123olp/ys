# ADR-0001 历史年表采用可复核数据管线与成熟发布工具组合

## 背景

Human Infra 需要把《永生史》做成严肃历史年表，而不是散文资料堆。年表必须满足四个要求：来源可追溯、日期可表达不确定性、事件可版本化、发布层可替换。

2026-08 对数字人文成熟工具做了联网调研与仓库活跃度核验。结论是：不存在一个能同时满足采集、清洗、本体、版本、可视化、长期保存的全部要求的单一“最成熟工具”。

## 决策或结论

采用分层技术栈，不把任何单一工具作为唯一真相源：

```text
Zotero / Tropy 采集
  -> OpenRefine 清洗
  -> Git + JSON Schema 年表数据
  -> EDTF 日期；PeriodO / CIDOC-CRM 时期与事件语义
  -> TimelineJS / D3 发布
  -> Omeka S / Neatline 仅按需引入
```

默认核心链是：

```text
Git + JSON Schema -> TimelineJS / D3 -> CI 门禁
```

## 证据

2026-08-06 核验到的维护事实：

| 工具 | 核验结果 |
| --- | --- |
| PeriodO | 官方客户端 `periodo/periodo-client` 最近提交 2026-08-05，CC0 许可，提供 JSON/CSV/Turtle 数据集下载 |
| TimelineJS | NUKnightLab/TimelineJS3 活跃，支持 JSON 配置与 ES6 导入 |
| Wikibase | 活跃，是 Wikidata 背后的开源知识图谱软件 |
| Omeka S | 活跃 |
| OpenRefine | 活跃 |
| Tropy | 活跃 |
| Heurist | 活跃 |
| D3 | 活跃 |
| Neatline S | 维护较弱，约 2023-03 后停滞 |
| Recogito2 | 维护较弱，约 2023-01 后停滞 |

因此，Neatline 和 Recogito2 不进入核心链路；PeriodO 作为时期 gazetteer 参照使用，不强制自托管客户端。

## 影响范围

- `docs/reference/history-timeline/TOOLS.md` 记录推荐链与工具核对。
- 年表 JSON Schema、GATE-0002、GATE-0003 继续作为机器门禁。
- 可视化发布层允许替换，但不得绕过 Git + JSON Schema 真相源。
- 不引入需要固定 SaaS 或无法导出标准格式的工具。
