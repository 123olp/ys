# 候选站点研究快照

## 视觉与进度树

### Calitree

最接近 Human Infra 的节点状态语言。公开页面明确给出 Locked、Available、In Progress、Completed 四态，进度以节点外围增长弧表示，支持点击详情、拖动平移和缩放。适合借鉴节点点亮、环形进度和“通过测试而非记录活动”的验收逻辑。

### Tree

最接近 Human Infra 的依赖解锁模型。任务是图节点，完成前置任务后下一层自动点亮，其他节点保持灰色；同时提供分支比较和可选战争迷雾。其核心价值是把图设为真相源，列表和时间线只是图的投影。

### roadmap.sh

最成熟的节点内容组织参考。路线节点连接学习资源、指南和进度，适合借鉴“概览图 -> 节点详情 -> 外部资料”的阅读路径。Human Infra 应替换学习完成度，改用研究、证据、验证和工程成熟度。

### Path of Exile Passive Skill Tree

适合研究超大规模图的导航和路径聚焦：密集节点、远近缩放、路径高亮和全屏浏览。Human Infra 只借鉴导航机制，不采用游戏美术和极端节点密度。

### SkillTrees & RoadMaps

自由编辑型技能树参考，重点是节点拖拽、关系连接、状态编辑和平移缩放。适合作为未来内部编辑器参考，不适合作为公开证据页面的完成判定来源。

### CortexTree

提供拖放连接、颜色文件夹、JSON 导入导出、网格吸附、缩放和撤销重做。可借鉴数据可携带性与编辑历史，但公开阅读不能依赖登录。

### Calisthentials Skill Tree

使用 Locked、Unlocked、Good Form、Mastered 的连续状态，分别定义桌面和移动端手势，并把进度保存在浏览器本地。可借鉴跨端手势和本地状态，但不能用单击循环状态替代证据验收。

### Historical Tech Tree

适合展示跨越长时间尺度的技术谱系和历史关系。站点以纵向可缩放 DAG 承载 2,400 余个技术节点和 3,700 余条连接，节点可进入详情状态，主图数据由 `/api/inventions` 的 `{nodes, links}` 提供。Human Infra 可复用其“长时标、依赖边、节点详情、画布缩放”信息结构，但必须区分“历史先后”“影响关系”和“必要依赖”。公开源码 `etiennefd/hhr-tech-tree` 为 MIT；技术与连接数据不属于该 MIT 许可，图片还需逐项遵循 `/image-credits`。

### Factorio Technologies

研究节点具有前置条件、投入成本和解锁产物，且部分研究进度可保存。最适合借鉴“解锁需要什么、解锁后得到什么”，但科研成本和证据不能被压成单一游戏资源。

### seenodes

适合运营状态层：On track、At risk、Blocked、Complete，以及有向、实线和虚线关系。Human Infra 应把这些状态叠加在研究节点上，并同步提供文字和图标。

## 科研证据层

### ProbKnow

以论文、概念、主张和假设为节点，强调证据权重与时间变化。适合作为节点证据抽屉和主张关系参考，但实验性平台本身不构成证据权威。

### 3ie Evidence Gap Maps

通过交互矩阵展示证据聚集与证据空白，并连接摘要和全文。适合 Human Infra 的“证据覆盖图”，尤其用于区分“研究很多”与“关键终点仍缺证据”。

### Open Research Knowledge Graph

把论文贡献转换为结构化知识并支持比较。适合作为机器可读研究关系参考，但外部图谱只能作为来源入口，不能直接替代项目 fresh review。

### MIRA

围绕研究问题、主张和证据建立可引用记录。可借鉴节点之间的语义类型和引用结构，Human Infra 仍需保留自己的 Claim ID、Source Card、反证和降级契约。

## 实现与门禁

### React Flow

成熟的节点式 React UI 引擎，提供自定义节点、边、拖动、缩放、平移、选择、小地图和控制器。它适合最终多父依赖 DAG；若采用，应作为 Astro 交互岛，而非重写整个站点。

### React Flow Examples

重点参考 Dagre、ELK、折叠展开、自动布局、节点工具栏和大图模式。实现时优先使用 ELK 处理复杂层级和多边依赖。

### react-d3-tree

基于 D3 层级布局的交互树，适合严格单父结构和快速原型。Human Infra 存在多父依赖与跨分支证据关系，因此它更适合原型，不宜成为最终图模型。

### NASA Technology Readiness Levels

提供 1-9 级成熟度语言，适合把“研究过”“验证过”“工程可用”分开。Human Infra 应建立领域适配后的成熟度门禁，不机械照搬航天硬件等级。
