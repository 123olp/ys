# 历史年表治理

## 1. 治理目标

保证年表是“严肃历史”而非“未来学叙事”或“资料堆砌”。所有事件都必须可追溯、可复核、可降级、可回滚。

## 2. 角色

| 角色 | 职责 |
| --- | --- |
| 年表编辑 | 新建事件、维护来源、填写字段、保持结构一致 |
| 本地复核员 | 校验来源上下文、日期边界、证据等级和禁止用途 |
| 独立审阅员 | 对事件做 fresh review，不沿用编辑的自我判断 |
| 作品集成员 | 把已复核事件写入公共永生史 |
| 治理管理员 | 维护 Schema、契约、门禁和更新周期 |

## 3. 生命周期

```text
draft
  -> locally_reviewed
  -> fresh_reviewed
  -> published

needs_revision
  -> draft

blocked
  -> needs_revision
  -> draft

superseded
  -> archived
```

状态定义：

| 状态 | 含义 |
| --- | --- |
| draft | 已录入，未复核 |
| locally_reviewed | 已完成本地来源语境复核 |
| fresh_reviewed | 已由独立审阅员复核 |
| published | 已进入公共作品或可视化 |
| needs_revision | 存在日期、来源或解释问题 |
| blocked | 来源不可达、证据冲突或禁止用途触发 |
| superseded | 被更新事件或更权威来源取代 |
| archived | 只读保留，不再参与当前年表 |

## 4. 审阅要求

### 本地复核

- 核对来源 URL/DOI 是否真实可达。
- 核对日期是否与来源一致，不夸大精确度。
- 核对证据等级是否与来源类型匹配。
- 核对事件解释是否包含不可支持的推论。

### 独立审阅

- 不直接复用编辑写的结论。
- 至少检查：事件 ID、日期、来源、证据等级、路径族、禁止用途。
- 对“待考证”事件不得升级为已证明。
- 对高风险断言必须明确写下降级条件。

## 5. 质量门禁

任何事件进入 `published` 前必须满足：

```text
Schema 校验通过
来源卡已注册且来源可访问或已登记元数据
时期 ID 已注册，PeriodO 映射状态为 matched 或显式 pending
event_id 唯一
必填字段齐全
日期格式合法
证据等级合法
本地复核完成
独立审阅完成
无禁止用途触发
```

机器门禁：

```bash
make history-timeline-gate
```

CI 已接入 `.github/workflows/check.yml`，每次 push 和 pull_request 都会先运行该门禁。

## 6. 更新周期

- 常规复查：每季度一次。
- 重大来源出现：随时触发，例如新档案公开、重要论文发表、日期争议解决。
- 公共正文引用：只跟随 `published` 事件。
- 来源失效：24 小时内将事件置为 `needs_revision` 或 `blocked`，不得继续引用。

## 7. 冲突处理

- 来源之间存在日期争议时，保留多个来源，`claim` 使用“据某来源”表述。
- 无法判断时，状态为 `blocked` 或 `needs_revision`，不强行合并。
- 治理管理员与独立审阅员意见冲突时，保持最保守状态，不升级。

## 8. 回滚与版本

- 年表数据纳入 Git 版本管理。
- 每次批量改动前创建可回滚基线。
- 删除事件必须改为 `archived`，不物理删除已审阅记录。
- 来源 URL 变化时更新访问日期，不静默替换。
