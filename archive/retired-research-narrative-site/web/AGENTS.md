# web 目录说明

`web/` 是 Human Infra 的 Astro + D3 Web 应用目录，用于把科研叙事、书籍转译、预测模型和可视化组织成可发布的多页站点。

## 目录结构

```text
web/
├── AGENTS.md                    # 本目录架构说明
├── CLOUDFLARE.md                # Cloudflare Pages 发布、验证与回滚契约
├── GEO.md                       # GEO 方法、度量边界和执行契约
├── README.md                    # 运行方式、页面职责和边界
├── astro.config.mjs             # Astro 配置
├── package.json                 # Web 应用依赖与脚本
├── wrangler.toml                # Cloudflare Pages 官方部署配置
├── public/                       # 静态发布资源和 vendored 前端资源
├── scripts/                      # 本地生成器、数据导出器和 GEO 审计器
└── src/
    ├── components/              # Astro 页面组件
    ├── data/                    # 小型结构化展示数据和派生审计产物
    ├── lib/                     # 实体、URL、研究域与证据图只读发布适配层
    ├── layouts/                 # 页面布局
    ├── pages/                   # Astro 路由页面
    │   └── papers/              # 独立论文页路由
    ├── scripts/                 # D3 图表脚本
    └── styles/                  # 全局视觉系统
```

## 职责边界

- `GEO.md` 是 Web 生成式引擎优化的方法与度量契约；它区分本地可验证的发布就绪度与必须通过外部采样观测的 AI 引用效果。
- `src/lib/site.ts` 是公开实体、发布者、规范 URL、部署基路径和公开页注册表的单一真相源；Cloudflare 根路径与 GitHub Pages 子路径必须由构建环境注入，页面不得硬编码第二套公开地址。
- `CLOUDFLARE.md` 与 `wrangler.toml` 定义 Cloudflare Pages 的构建、公开源站、直接上传和回滚边界；Pages 只发布 `dist/`，不运行 MediaWiki 或数据库。
- `src/lib/domain-registry.ts` 只在构建期读取 `domains/_possibility-space-control/classification.tsv`，将其投影为研究域索引；不反向修改研究域真相源。
- `src/lib/evidence-registry.ts` 只读连接 `docs/reference/` 中的主张、反证、字段和来源锚点寄存器，构建失败即拒绝缺失或重复 ID；它不得成为新的人工证据真相源。
- `src/pages/about.astro`、`src/pages/research-map.astro` 和 `src/pages/evidence-map.astro` 是项目实体、C1-C6 研究域与有界证据关系的人类可读入口。
- `src/pages/robots.txt.ts`、`llms.txt.ts`、`llms-full.txt.ts`、`knowledge-index.json.ts`、`evidence-graph.json.ts`、`geo-prompt-bank.json.ts` 和 `geo-metrics.json.ts` 组成机器可读发布面；知识和证据索引必须保留研究边界，监测指标不得伪造外部 AI 平台观测值。
- `src/data/geo-monitoring-prompt-bank.json` 是可重复外部 AI 采样的提示注册表，只定义问题与分类，不保存未经观测的排名、引用或推荐结论。
- `scripts/audit-geo-readiness.mjs` 审计构建产物的规范链接、结构化数据、语义容器、机器端点、站点地图、Pages 子路径和证据图引用完整性；PASS 只表示技术发布与有界关系投影就绪，不表示已被收录、引用或独立验证。
- `src/pages/*.astro` 是页面真相源，负责叙事结构、页面路由和内容组织。
- `src/pages/index.astro` 是 Web 首页与成熟度状态入口，直接消费 `docs/reference/human-infra-maturity-gap-register.json` 展示三轴成熟度、未完成 gate 和下一步 work orders；不得把早期 70/35/10 旧评估重新写入页面，也不得把 partial / blocked gate 表达成完成。
- `src/pages/papers/effective-immortality-flywheel.astro` 是有效永生飞轮的独立论文页，复用 PaperReaderLayout，不覆盖旧 `/paper/`。
- `src/pages/papers/metric-redshift-recursive-waiting.astro` 是度规红移递归等待假设的独立论文页，复用 PaperReaderLayout，不覆盖旧 `/paper/` 或有效永生飞轮论文页。
- `src/pages/papers/proper-time-differential-waiting-hypothesis.astro` 是度规红移固有时差分路径的专项论文页，由 arXiv HTML Paper Reuse Kit 生成 seed 后维护正文，消费 `src/data/proper-time-differential-waiting-hypothesis.json`，复用 PaperReaderLayout，不覆盖其他论文页。
- `src/pages/papers/controllable-metric-waiting-room-hypothesis.astro` 是可控度规等待室假设的专项论文页，由 `tools/arxiv_html_paper_tool.py write-page` 新建 seed 后维护正文，消费 `src/data/controllable-metric-waiting-room-hypothesis.json`，用于承载“等待室 -> 技术升级 -> 退出采用 -> 再等待”的递归未来等待假设。
- `src/pages/lev.astro` 是长寿逃逸速度路线页，消费 `src/data/lev-model.json` 展示 R1-R9 主流路线、概率门、多阶效应、正向飞轮和负向反噬链路。

- `scripts/audit-controllable-metric-waiting-room-pre-submission-review.mjs` 是本地可控度规等待室预提交审查器，读取结构化数据、页面源码、reference verification、citation context packet 和 citation context local review，输出 working paper 边界、非预测器边界、外部审查边界、文风和阻塞项账本；它不替代正式同行评议。
- `scripts/audit-pre-submission-review.mjs` 是本地预提交审查器，读取论文、页面、source-notes、结构化数据和已生成 audit ledger，检查版本漂移、必需边界、机械文风问题和提交前阻塞项，输出 pre-submission review 账本。
- `scripts/export-citation-context-review-packet.mjs` 是本地外部审查输入包生成器，读取 Claim Register、Claim Evidence Map、Citation Context Register 和 Reference Registry，输出 fresh reviewer 可消费的 citation-context review packet。
- `scripts/audit-citation-context-risk-triage.mjs` 是本地 L3 引用语境风险分诊器，读取 citation-context review packet、Reference Verification 和 Claim Context Audit，输出外部 reviewer 的优先级队列；它不替代 fresh reviewer 结论。
- `scripts/audit-high-risk-citation-contexts.mjs` 是本地 HIGH/BLOCKER 引用语境来源边界审查器，读取 citation-context risk triage、Reference Verification 和结构化证据，只审最高风险上下文；它可以收窄提交前队列，但不替代 fresh reviewer 逐句判断。
- `scripts/audit-citation-context-local-review.mjs` 是本地全量引用语境来源边界审查器，读取 citation-context review packet、risk triage、Reference Verification、Claim Context Audit 和 high-risk review，覆盖 CTX1-CTX12；它固定 safe use、forbidden use、reference state 和 reviewer focus，但不替代 fresh reviewer 逐句判断。
- `scripts/export-fresh-reviewer-citation-audit-protocol.mjs` 是外部 fresh reviewer 审稿协议导出器，读取 citation-context packet、risk triage、local review、high-risk review、Reference Verification 和 Citation Audit，输出 reviewer independence contract、pass gate、review queue 和逐项 prompt；它不替代 reviewer verdict。
- `scripts/export-fresh-reviewer-context-packets.mjs` 是外部 fresh reviewer 分件包导出器，读取 fresh reviewer protocol，把 CTX1-CTX12 拆成独立 JSON/Markdown packet 和结果 stub，便于逐条外部审稿；它不替代 reviewer verdict。
- `scripts/export-fresh-reviewer-handoff.mjs` 是外部 fresh reviewer 单文件交接包生成器，读取 fresh reviewer protocol、packet index 和全部 CTX packet，输出 `fresh-reviewer-context-packets/HANDOFF.json`、`HANDOFF.md`、`RESULT_SCHEMA.json` 与 `RESULT_SCHEMA.md`；它把 independence contract、返回文件清单、verdict schema、阻塞条件、结果回填 schema、source trace 和完整 packet 内容合并成独立消费包，但不得生成 reviewer verdict。
- `scripts/audit-fresh-reviewer-handoff.mjs` 是外部 fresh reviewer handoff 审计器，验证 `HANDOFF.*`、`RESULT_SCHEMA.*`、`INDEX.*` 和各 CTX packet 的覆盖、schema 编译、source trace hash、结果文件清单和 Markdown 完整性，输出 `HANDOFF_AUDIT.json` 与 `HANDOFF_AUDIT.md`；它不替代 reviewer verdict。
- `scripts/assemble-fresh-reviewer-citation-results.mjs` 是外部 fresh reviewer 结果汇总器，读取 `fresh-reviewer-context-packets/results/CTX*.json`，先用 Ajv / `RESULT_SCHEMA.json` 做 JSON Schema 校验，再执行本地语义门禁；只有全部 12 个 context 齐全且结构校验通过后，才生成正式 `FRESH_REVIEWER_CITATION_AUDIT_RESULTS.json` 并写入每个输入文件的 SHA-256；它不得生成或推断 reviewer verdict。
- `scripts/audit-fresh-reviewer-citation-results.mjs` 是外部 fresh reviewer 结果账本审计器，生成 reviewer results 模板，若存在真实 `FRESH_REVIEWER_CITATION_AUDIT_RESULTS.json` 则验证它是否由 assembler 生成、是否能回到逐项 `results/CTX*.json` 输入文件、hash 是否匹配、每个 context 的 reviewer verdict、source URL、resolution status 和 blocking conditions；它不得生成伪 reviewer 结果。
- `src/layouts/PaperReaderLayout.astro` 直接复用 `public/static/browse/0.3.4/` 和 `public/use.typekit.net/` 中下载并归一化的 arXiv HTML papers CSS/JS/图标/字体资源；模板真相源沉淀在 `../tools/arxiv-html-paper/templates/`，不维护自定义论文阅读器样式或控件脚本。
- `src/components/` 保存可复用的 Astro 页面组件。
- `src/data/` 保存 Web 展示所需的小型结构化数据，不保存原始研究数据、医疗数据或个人数据。
- `web/dist/` 是构建产物，不进入版本库。
- 根目录 `singularity-human-infra.html` 保留为历史静态专项页；新的正式 Web 版本以 `web/` 为主。

## 维护规则

- Cloudflare Pages 生产构建使用 `/` 根路径，GitHub Pages 回滚构建使用 `/human_infra` 子路径；新增内部链接必须通过 `site.ts` 的 URL helper 生成，不得假定固定部署路径。
- 修改公开页、实体元数据、机器端点、站点地图或 Pages 配置后，必须同时运行 `npm run audit:geo` 和 `PUBLIC_SITE_ORIGIN=https://human-infra.pages.dev npm run audit:cloudflare`；外部 AI 效果仍必须按 `GEO.md` 的固定提示库与采样周期独立记录。
- 新增页面时，必须同步更新 `README.md` 和本文件目录结构。
- 新增图表时，优先复用 `src/scripts/model-charts.js` 和 `src/scripts/evidence-graph.js` 的 D3 绘图约定；证据型图表优先消费 `src/data/` 的结构化数据。
- 新增论文式长文时，优先使用 `tools/arxiv_html_paper_tool.py write-page` 生成工具 seed，再用 `ltx_*` 语义结构和 PaperReaderLayout 承载正文；不得改写 arXiv 下载资源的样式和控件逻辑，只替换正文内容。
